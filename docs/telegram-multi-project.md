# Два проекта в одном Telegram-боте

Бот [@GymAppEditBot](https://t.me/GymAppEditBot) создаёт GitHub Issues в одном из двух репозиториев:

- **🏋️ Gym App** → [pavelmashina/gym-app](https://github.com/pavelmashina/gym-app/issues)
- **🐾 Рядом** → [pavelmashina/ryadom-app](https://github.com/pavelmashina/ryadom-app/issues)

## Создание новой задачи

1. Нажми кнопку **🆕 Новая задача**.
2. Нажми кнопку выбора проекта **🏋️ Gym App** или **🐾 Рядом**.
3. Отправь текстовое описание и до шести скриншотов. Изображения PNG/JPEG/WebP, до 8 МБ каждое.
4. Нажми **✅ Отправить**.
5. Бот вернёт ссылку на Issue **в выбранном репозитории** и укажет название проекта.

Вместо кнопок можно использовать команды `/new`, `/gym`, `/ryadom`, `/create`. Команда `/project` показывает доступные проекты.

**Важно:** после добавления текста или фото в черновик нельзя переключить его на другой проект. Отмени черновик кнопкой **❌ Отмена** и создай новый. Это защищает от случайной отправки задачи не в тот репозиторий.

## Совместимость и разделение черновиков

- Старые черновики и Issues остаются в Gym App; задача не переадресуется из-за обновления кода.
- В личной беседе *текст без активного черновика* по-прежнему сразу создаёт Issue в Gym App. Для задач «Рядом» сначала выбери соответствующую кнопку.
- В привязанном Telegram-топике сначала нужно открыть черновик и выбрать проект. Сообщения вне привязанного топика игнорируются.
- Черновики разных людей в одном топике изолированы по user ID. Авторизация через `/allow` и `/revoke` не изменена.
- Скриншоты хранятся в том же публичном Supabase Storage bucket и прикладываются к Issue того проекта, который выбрал отправитель.
- **Голосовые отключены.** ПК для отправки текстовых задач не нужен.

## Права доступа к GitHub

Бот использует Supabase Edge Function с секретом `GITHUB_ISSUES_TOKEN` для Gym App. Для «Рядом»:

- Если существующий fine-grained PAT включает **оба** репозитория с правом **Issues → Read and write**, ничего добавлять не нужно.
- Если текущий PAT ограничен только Gym App, создай отдельный fine-grained PAT **только для `ryadom-app`** и сохрани в [Supabase Secrets](https://supabase.com/dashboard/project/sjggdpyficjkpcmybbfr/functions/secrets) под именем **`GITHUB_ISSUES_TOKEN_RYADOM`**. Старый токен останется без изменений.

Ключи сюда, в Telegram или GitHub **не присылай**. Бот выбирает правильный GitHub-токен по проекту, проверяет наличие дубликата и создаёт Issue только в указанном репозитории.

## Статусы

Для обоих репозиториев используются одинаковые labels:

- **Новая задача** — добавлена и ещё не выполнена
- **Выполнена** — правки сделаны, ждут личной проверки
- **Проверена** — владелец проверил; GitHub Issue закрывается

Статус «Новая задача» присваивается новым Issues GitHub Actions. Старые закрытые задачи не меняются. Проверять приложение и переводить задачу в «Проверена» должен сам владелец.

## Тест после подключения

- Отправь текстовую задачу в Gym App — Issue должен появиться только в `gym-app`.
- Отправь отдельную текстовую задачу в «Рядом» — Issue должен появиться только в `ryadom-app`.
- Отправь скриншот и текст в «Рядом»; проверь изображение и статус в Issue.
- Попробуй переключить проект после добавления текста — бот должен попросить сначала отменить текущий черновик.
- Отправь `/rules` в личной беседе и привязанном топике — должны отображаться обе кнопки проекта.
