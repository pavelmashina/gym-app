# Форматы результатов v2 — локальный контракт

Реализация: src/lib/exerciseResultsV2.js, тесты: tests/exercise-results-v2.mjs.
Контракт подключён к локальной SQL-миграции result_v2, вводу, истории, отчёту и статистике.
В production не включён. Актуальные ограничения — implementation-status.md.

| Формат | Завершённый подход требует | Сравнение |
|---|---|---|
| weight_reps | вес, повторения | больше веса при тех же повторах либо больше повторов при том же весе |
| bodyweight_reps | повторения | больше повторов при одинаковом дополнительном весе |
| assisted_reps | повторения, помощь | меньше помощи при тех же повторах; больше повторов при той же помощи |
| duration | секунды | дольше удержание |
| carry | вес и расстояние/время | одинаковый вес; дистанция-only, время-only либо дистанция за одинаковое время |
| cardio | секунды; дистанция необязательна | меньше времени на одинаковую дистанцию либо больше дистанции за одинаковое время |

Если цель сравнения неоднозначна, возвращается null (несопоставимо), не выдуманный
силовой рейтинг. Для кардио только с длительностью нет автоматического «лучше».
Все контексты должны совпадать: упражнение, формат, способ нагрузки, кг, настройки,
латеральность, сторона и экземпляр оборудования. Для stack/plates/assistance
экземпляр обязателен именно для сравнения; записать результат без него разрешено.

Разминка, незавершённые и legacy-записи не участвуют в сравнении v2. Старый расчёт
рекорда в workoutSessions.js не изменён. Противовес не попадает в вес или тоннаж.
Для гантелей результат объёма остаётся в условии «вес одной гантели × повторы»,
автоматического удвоения нет. Объёмы разных load_mode/экземпляров не суммировать.

Ввод: запятая или точка в десятичном числе; пустое значение = null, а не ноль.
NaN/Infinity, единицы в строке, отрицательные значения и дробные повторы отклоняются.
Ноль допустим для помощи и дополнительного веса, но не для секунд/расстояния.
У одностороннего или независимого выполнения обязательна сторона left/right.

## Реализованные проверки

1. Снимок measurement/load/config на подходе; запрет незаметного изменения его смысла.
2. Добавляющая SQL-миграция: completed допускает валидный result_v2 вместо legacy reps.
3. Проверки SQL и RLS на полной схеме, соответствующие этому контракту.
4. Адаптация ввода, завершения сессии, предыдущих результатов, статистики и отчётов.
5. Отдельный маршрут legacy_v1 без пересчёта прежних показателей. Нельзя включать
   запись v2 раньше, чем старые читатели перестанут считать её обычными weight/reps.

Настройки сериализуются в configuration_key с префиксом settings-v1: и фиксированным
порядком значений. Ширина хвата 0–200 см, угол скамьи −90…90°, строки до 500 символов.
Пустые значения остаются неизвестными, не превращаются в нули. Сохранённый шаблон
не определяет историю: изменение шаблона не меняет снимок ранее записанного подхода.

Перед включением остаётся удалённый staging-прогон через Auth/PostgREST и два устройства.
Локальная проверка актуальной схемы: tests/exercise-catalog-live-integration.mjs.
