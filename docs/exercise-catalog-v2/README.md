## Зависимости

catalog_programs.source_payload → adopt_catalog_program → programs → program_weeks →
program_workouts → program_workout_exercises → program_exercise_sets.

program_workout_exercises → scheduled_workout_exercises → scheduled_sets;
scheduled_workout_exercises → workout_session_exercises → performed_sets.

exercises.id используется program_workout_exercises, scheduled_workout_exercises,
workout_session_exercises (ON DELETE RESTRICT), user_recent_exercises (CASCADE).
В сессиях отдельно хранится note. Снимки названий и предписаний сохранять.

## Проблемы

1. В exercises нет семейств, aliases, canonical_key и структурированной техники.
2. Глобальный UNIQUE(name) препятствует одинаковым названиям личных упражнений
   разных владельцев. Удалять ограничение можно только после исправления импорта:
   adopt_catalog_program сейчас сопоставляет по имени, ORDER BY id LIMIT 1.
   Это не правило канонической идентичности.
3. В исходных программах встречаются «Суперсет:», несколько движений в одной строке,
   усечённые названия с многоточиями, неопределённые «Приседания», «Жим ногами».
   Нельзя назначить им произвольный UUID или потерять структуру комплекса.
4. exerciseLibrary.js определяет оборудование по строкам при отсутствии явного поля,
   неизвестное становится «Тренажёр». Поиск не знает aliases и семейства.
5. performed_sets имеет только weight/reps; workoutSessions.js рассчитывает силовой
   показатель из них. Продолжительность, помощь, дистанция, сторона не представлены.
6. Личные упражнения уже находятся в exercises с owner_id. Отдельная физическая
   user_exercises дублировала бы модель и усложнила все внешние ключи.
7. Политики exercises ограничивают личные записи владельцем, UPDATE имеет USING и
   WITH CHECK. Это проверка определений, НЕ полноценный тест изоляции двух пользователей.

## Вторая локальная контрольная точка

- `20261015090011_exercise_machine_profiles.sql`: типовые профили, связь с упражнениями,
  личные экземпляры, настройки выполнения. Бренд не создаёт упражнение. Неизвестная
  траектория/конструкция остаётся NULL, помощь отделена от обычной нагрузки.
- Настройки могут ссылаться только на доступное упражнение и свой экземпляр совместимого
  профиля. Смена владельца, ID или профиля существующего экземпляра запрещена.
- Проверены оба повторных запуска SQL, чтение/изменение/удаление между двумя владельцами,
  запрет чужого экземпляра и чужой карточки, запрет недопустимого угла скамьи.
- `data/exercise-catalog/reference-cards.mjs`: шесть карточек из раздела 7 ТЗ с
  индивидуальными инструкциями, мышцами, оборудованием, ru/en aliases и форматом записи.
  Все остаются review — программная проверка не заменяет редакционную проверку контента.
- Подтверждены UUID жима штанги лёжа, приседа со штангой на спине, румынской тяги со
  штангой и планки на предплечьях. У двух старых записей equipment ошибочно «Тренажёр»:
  штанга прямо указана в технике. Исправление пока только в локальных новых карточках.
- Подтягивание широким прямым хватом не приравнено автоматически к общему прямому хвату;
  широкие/узкие отжимания не превращены произвольно в общий вариант. У двух карточек
  id=null, что блокирует их импорт через проверку identity. Новые UUID им не выданы.
- `src/lib/exerciseCatalogV2.js`: чистые функции проверки карточки и поиска по названию,
  aliases, семейству и оборудованию с совместными фильтрами. Поиск учитывает ё/е,
  регистр и дефисы. Пока НЕ подключён к рабочим экранам и НЕ является защитой доступа.
- `tests/exercise-catalog-v2-content.mjs`: содержимое шести карточек, четыре существующих
  UUID, две заблокированные идентичности, сочетание поиска/фильтров, ограничения метрик
  и обязательность источников/прав для будущих медиа.
