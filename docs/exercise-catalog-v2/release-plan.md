# Выпуск новой базы без платных функций

Ограничение владельца: не создавать платные проекты, ветки, подписки и дополнения.
Все подготовительные проверки выполняются локально. Docker не требуется: используется
уже установленный PGlite. Рабочая база не служит тестовым стендом.

## Состав

- 109 обязательных канонических карточек: 21 существующий UUID и 88 новых.
- Все 436 исходных общих UUID сохраняются. Итого после заполнения — 524 общих записи.
- Прежние названия 21 обновляемой карточки остаются алиасами.
- 415 остальных записей остаются legacy, без переименования и без переноса результатов.
  Их соответствие новым карточкам НЕ подтверждено. Это сознательный безопасный режим
  переноса, а не утверждение, что все смысловые дубли устранены.
- Составные/неоднозначные названия программ сохраняются текстовыми снимками. Не назначать
  им первое похожее упражнение, не делить суперсеты автоматически, не терять предписания.

## Бесплатная проверка

`node scripts/verify-catalog-release.mjs`

Проверяет 16 наборов тестов и обе сборки интерфейса. Интеграционный тест восстанавливает
15 таблиц и 23 функции из снимка реальной структуры, создаёт вымышленных пользователей
и контрольную старую тренировку. Затем проверяет полный откат при поздней ошибке,
успешное повторное применение, сохранение истории, все 436 старых названий,
импорт всех 376 названий программ с вариантами предписаний и новые форматы результатов.
Ни запросов к рабочей базе, ни платных ресурсов этот запуск не создаёт.

## Единая транзакция переноса

`node scripts/exercise-catalog-release.mjs`

Команда только выводит SQL. По умолчанию новые карточки имеют статус review.
`--publish` формирует вариант с опубликованными карточками, но также ничего не исполняет.
Пакет проверяет наличие исходных UUID, применяет четыре существующие миграции и данные
в одной транзакции, затем проверяет полноту. Ошибка отменяет весь пакет. Таймаут
ожидания блокировки — 5 секунд, отдельного оператора — 120 секунд.

Это артефакт репетиции/контролируемого выпуска, не автоматический деплой и не замена
учёта миграций Supabase. При реальном выпуске необходимо сверить журнал миграций,
сохранить актуальную резервную копию и зарегистрировать применённые миграции штатно.
Не повторять пакет после ручного редактирования опубликованных карточек без проверки:
идемпотентность не означает сохранение произвольных последующих редакторских изменений.

## Что локальные тесты не подтверждают

Сетевые сбои, настоящий Auth/PostgREST и синхронизацию двух устройств. Для этих проверок
платная ветка не обязательна, но отдельная безопасная среда сейчас не настроена.
Флаги интерфейса остаются выключенными до согласованного выпуска. Старые результаты
не пересчитываются. Медиа без подтверждённых прав не добавляются.
