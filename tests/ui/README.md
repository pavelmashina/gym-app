# Проверка черновика и фильтров

Из корня проекта: `node node_modules/vite/bin/vite.js --config tests/ui/vite.config.mjs`.
Открыть `http://127.0.0.1:4173/tests/ui/index.html`.

Стенд использует настоящие компоненты и тестовые сервисы. Запросы к рабочим программам и упражнениям заменены локальными фикстурами; авторизация не нужна. Страница не включена в production entrypoint.

Проверенные вручную сценарии 14 октября 2026:

1. Назвать программу, добавить тренировку, изменить её имя, выбрать упражнение. Перезагрузить до нажатия «Готово»: восстановлены редактор, имя и выбранное упражнение.
2. Ввести 12 повторений и вернуться стрелкой к циклу. Повторно открыть тренировку: значение осталось.
3. На шаге расписания выбрать ритм Пн/Ср/Пт и дату. Перезагрузка восстанавливает шаг, ритм и дату.
4. Имя программы, начинающееся с «Ошибка», вызывает тестовый отказ сохранения. После отказа и перезагрузки черновик остаётся.
5. Изменить имя на «Сила — тест», сохранить и начать позже. После успешного тестового ответа и перезагрузки конструктор пуст.
6. В личных программах включить «Дом» + «Сила»: из трёх карточек остаётся одна. Добавить поиск «кардио»: пустой результат с кнопкой сброса. Сброс возвращает все три карточки.

Дополнительные автоматические проверки: `pnpm run test:drafts` (изоляция аккаунтов, повреждённые записи, ошибки хранилища, совместные условия и сброс).

Ограничения: черновик новой программы хранится в текущем браузере, не синхронизируется между устройствами. Обложка-файл в черновик не входит; интерфейс предупреждает о повторном выборе после перезагрузки. Существующие программы и запуск из каталога используют прежний сценарий загрузки, локальный черновик новой программы на них не накладывается.

## Стенд «Мои упражнения»

Тот же стенд: `http://127.0.0.1:4173/tests/ui/index.html?screen=my-exercises`. Базу заменяет `sessionStorage` вкладки, поэтому созданное и изменённое видно после перезагрузки; закрытая вкладка возвращает исходные записи.

Состояния: `&state=empty` (пустой список, пока вкладка ничего не сохранила), `&state=error`, `&state=slow` (долгая загрузка), `&usage=fail` (не удалось проверить связи при удалении). У «Жима из моей программы» есть связи с программами и историей, остальные записи свободны. Имя, начинающееся с «Ошибка», вызывает отказ сохранения при редактировании.

## Стенд активной тренировки

Из корня проекта: `node node_modules/vite/bin/vite.js --config tests/ui/workout.vite.config.mjs`.
Открыть `http://127.0.0.1:4174/tests/ui/workout.html?exercises=14&sets=6`: параметры задают длину списка.

Настоящие экраны тренировки, стили и жест «Назад» на тестовых сервисах из `workout-mock-services.js`, авторизация не нужна. Чтобы открыть стенд с телефона в той же сети, добавьте к команде `--host`. Длительность рендеров списка копится в `window.__workoutRenders`.

Второй вид плашки (строки «результатов v2» с подписями полей и «Настройками выполнения») появляется с `&v2=1`, если стенд запущен с `VITE_EXERCISE_RESULTS_V2=true`: у второго упражнения есть паспорт измерения, его подходы пусты. Сохранённые порядки подходов копятся в `window.__setOrderSaves`; `&order=fail` делает сохранение порядка неудачным, чтобы проверить откат.

«Добавить упражнение» под последней карточкой добавляет «Тестовый жим» с одним пустым подходом в конец тренировки до перезагрузки. В тренировке из программы сначала спрашивается, куда добавить: «Только в эту тренировку» или «Во всю программу». Выбранные упражнения и ответ копятся в `window.__exerciseAdds` как `{ exerciseId, scope }`. `&add=fail` делает добавление неудачным, `&exercises=0` открывает тренировку без упражнений, `&standalone=1` — разовую тренировку без программы: там вопроса нет.

Часы сессии лежат в `sessionStorage` под ключом `workout-fixture-clock` и считаются как на сервере: пауза и продолжение работают, а перезагрузка их не сбрасывает. Чтобы проверить паузу с другого устройства, задайте в этой записи `pausedAt` и верните вкладку на передний план; для отстающих часов телефона задайте `startedAt` в будущем.
